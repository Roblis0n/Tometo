# 长任务、并行与恢复

确需并行、长时间执行、压缩、跨会话交接或中断恢复时读取。普通短任务留在主会话完成，不引入调度系统。连续执行已授权工作，不把内部步骤变成逐轮等待用户批准的阶段。

## LR-01 先保持一个完整目标

保留原始请求、不可变约束、已授权范围和最终交付形式。分解的是工作，不是削减需求。内部子任务可以逐步完成，但最终由同一个集成人对照整体目标交付。

明确依赖顺序：会写入或依赖共同契约的实现任务，须先确定所需接口、可用输入和独占写入范围，再并行推进。只读调查、来源查证或备选设计比较，可以在接口或根因尚未确定时按不同问题并行；任务须能独立返回可定位的事实及未知，不得把未决方案直接写入共享产物。依赖调查结论的实施仍按顺序进行，这不等于先做试点再决定是否完成其余目标。

## LR-02 按证据和写入边界拆任务

适合并行的通常是独立来源查证、不同消费者审查、边界清楚的模块实现。共享同一未知根因时，可以让只读任务分别检查不同假设、信号或调用边界，再由主 Agent 汇合；不能把同一段摘要重复交给多人就称为独立取证。依赖该根因的共同修复须先收敛前提；多人争改同一文件或契约时先确定唯一写入者，不用更多实例互相覆盖。只读也不等于零影响，查询、扫描和采样仍须遵守访问范围与资源预算。

不同角色名不形成独立性。要分别覆盖不同假设、调用链或观察来源；主 Agent 应知道合并后还需要判断哪些交互。并行数量随真实工作和宿主能力，不固定配额，也不为了显得高效调用子代理。

## LR-03 子任务交付约定

真正派发时提供：共同的原始目标和必要约束、当前版本或工作区、该子任务要回答的问题、可读材料、独占写入范围、禁止动作、预期产物和集成人。保留原用户语义，不只发主 Agent 的结论摘要。

返回内容包括实际改动或可定位的事实、支持的结论、适用条件、未覆盖部分、冲突和下一项依赖。子代理没有足够原始规格时不得作完整规格符合性结论。用户只准只读审查时，所有子代理同样只读。

## LR-04 写入隔离不是形式

已有工作区足够隔离时复用。确需独立目录或 worktree 时沿项目工具建立，并保留用户已有改动和基线。不要让多个执行者同时生成同一文件，再靠最后写入者决定版本。

任务被撤回、重新分配或共同规格改变时，先终止或收回旧任务的写入所有权，再交给新执行者。不能可靠停止的旧执行者不得继续写共享目标；使用现有独立工作区保留其产物，由集成人审查后选择吸收。取消后的迟到结果不自动恢复写入权或推翻新基线，不为此建设通用调度平台。

共享运行环境、数据库、端口或构建目录也可能冲突；文件不同不代表资源独立。按本次实际争用资源确定串行入口或专属范围，不擅自增加基础设施。

## LR-05 主 Agent 必须集成实际产物

收到“完成”后读取产物、差异和证据定位，对照原目标检查相关契约与遗漏。合并重复发现，追查冲突前提；不把多个同源认可当作多数证明。

集成改变了接口、状态或数据流，就重新判断受影响的证据是否仍成立。两个单独模块都正确不推出组合正确。复用未受影响的依据，针对发生变化的组合取证，遵循[证据与完成](evidence-and-completion.md)，不机械重跑所有任务。

## LR-06 区分机械重做、有界采样与安全恢复

确定性失败若输入、实现、环境和观察方法均无变化，机械执行同一动作通常不能增加信息，应修正前提或换一个能区分解释的入口。新事实、新输入、新改动、新假设或环境恢复可以支持新的尝试，但不是要求重试前已经知道尚未取得的结果。

对并发、时序、随机性或测量噪声，重复运行本身可以是有价值的新采样。先明确要回答什么、哪些条件保持可比、沿已有资源预算怎样停止，再保留相关成功与失败结果；一次成功不抵消之前失败，不无限跑到绿。固定日志重复解释与读取同一回放，不伪装成新的运行样本；运行数也不直接等于统计独立样本数。

带外部副作用的重试另外要求协议支持安全重复、可确认状态或正确的恢复方式，遵循[兼容与交付](compatibility-and-delivery.md)。先辨别 SDK 或下层是否已经重试，避免叠加放大；沿现有期限、次数或流量预算限制恢复，不能绕过服务退避要求。这里不规定跨项目统一重试次数。

预算不足先去掉无关和重复工作，不秘密降低用户目标。局部障碍只阻挡依赖它的部分，其余授权工作继续完成；无限循环、自动推送、重置仓库或后台常驻不成为默认行为。

## LR-07 为恢复留下决定性信息

只有跨会话、压缩风险或中断确实需要时，更新项目已有任务记录；没有现成记录且任务需要恢复时，建立一份紧凑记录，不为每轮额外造档案。

保留原目标、约束、关键决定及原因、实际修改位置、可复用证据及其对应版本、已排除假设、仍未知状态、唯一下一入口。长日志和详细过程保留路径即可。不能在摘要中删掉失败证据，或把待确认内容改写成已完成。

## LR-08 恢复与最终交付

恢复时先核对实际文件、工作区和必要外部状态，记录是导航而非事实本身。发现现场变动就更新依赖判断，不在过期状态上接着写。涉及不确定外部副作用时先查询，见[兼容与交付](compatibility-and-delivery.md)。

最终区分子任务完成、主分支已集成、运行结果已观察及外部已生效。没有真实子代理工具时，由主 Agent 按同样问题划分顺序完成，并如实说明没有执行 fan-out；不得虚构代理、独立复核或后台工作。
