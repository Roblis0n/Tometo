# 证据与完成

需要作出运行、兼容或安全结论，完成依据有争议，或不同材料相互冲突时读取。本页规定结论如何成立，不建立固定测试阶段，也不要求每个任务生成证据表。代码、日志、测试、截图、规范和实际操作各自能证明不同东西。

## EC-01 原始目标不能被方便的指标替换

先保留用户要求的完整结果、必要约束和交付层级。用户要源码修改，源码层的完整修改就是交付对象，不能擅自要求上线；用户要可运行的用户路径，只创建源文件也不能冒充实际结果。

不得把“支持协议”缩成“接口同名”，把“所有指定行为”缩成“单个演示成功”，把“实际修复”缩成“没有报错”。目标确需改变时明确指出差异，不自行删除困难要求。进度、投入时间、输出行数或评论数都不是完成判据。

## EC-02 证据须对应具体结论

关键依据应能追到：哪份对象或产物、哪个版本或状态、哪些输入或操作及必要条件、观察到了什么、它支持哪一项结论。只需保留足以区分的定位，不必每次填写固定六栏表。

Git 提交号不能单独代表未提交改动；文件名不能单独代表实际加载版本。源码差异说明修改存在，运行记录说明某对象在某条件下表现如何，配置文件说明设置写入，宿主回执才说明相应加载事件发生。不能跨越这些层级直接推断。

区分原始输出、实施者自报、历史记录和本次独立核对。哈希一致证明这些字节相同，不证明内容真实、执行成功或已被宿主使用。复制上一轮来源登记时保留访问者、阶段与时点，不能自动改成自己本轮直读；缺少原始回执就按可取得的层级陈述，不因此推断报告造假。

## EC-03 证据有没有能力暴露失败

对承重结论问：若结论是错的，这份证据是否仍然可能出现？成功提示可能早于写入，空日志可能由错误过滤造成，通过的检查可能只重复实现中同一个假设。

当这种反例会影响交付，优先找不依赖该假设的观察，例如实际持久结果、独立契约、当前消费者或与实现分离的参考行为。这里的独立性来自信息和判据，不来自换了一个角色名。同一 Agent 可以写实现并取证，但不能让实现输出什么，成功条件就跟着变成什么。

不必对每个任务做故障注入、第二套实现或多代理评审。现有直接观察已能区分相关错误时就使用它。未发现反例不能变成“已证明不存在全部未知缺陷”。

## EC-04 区分证据种类及覆盖范围

| 材料 | 可以支持 | 不能自动支持 |
| --- | --- | --- |
| 当前源码和调用关系 | 逻辑、接线和可达路径的判断 | 当前生产实例确实执行了它 |
| 日志、追踪、运行输出 | 被记录对象在对应条件下的事件 | 未记录事件不存在，或过滤范围完整 |
| 截图、录屏、界面操作 | 指定画面或操作曾发生 | 后台持久化、权限或所有状态正确 |
| 类型、构建、已有自动检查 | 各自实际检查到的条件成立 | 整个产品满足全部需求 |
| 测试或参考系统对照 | 对应输入和行为范围的结果 | 未覆盖路径、所有版本或生产兼容 |
| 评审报告、关闭的线程 | 某人给出了判断或改变了线程状态 | 缺陷已经修好、意见必然正确 |
| 模拟器、mock、回放环境 | 它实际建模或保存的契约与轨迹 | 被省略的权限、隔离、故障或真实服务行为 |
| 形式化证明、模型检查结果 | 在声明的模型、假设和检查范围内的性质 | 未建模环境、模型与实现对应关系或实际运行均正确 |

不把表中弱结论表述为强结论；也不因为一种证据不全能就否定它在对应范围内的价值。使用模拟、回放或形式化结果时，先查这次关键行为是否真的纳入其模型与假设，不把“工具很强”当覆盖证据。安全主张尤其要能区分允许和应被拒绝的情况；工具明确不实现该控制时，结论留在它能支持的范围，不擅自转向付费或生产操作。

有界重复运行取得的失败、超时和排除样本应保留相关定位及解释，不能只挑最后一次成功。重复同一轨迹不增加独立样本；新运行也未必统计独立。没有足够样本与适用设计，就不声称失败概率、可靠性提升或全部缺陷已消除。

## EC-05 证据有失效范围

修改相关实现、配置、依赖、数据语义或集成状态之后，判断哪些原结论受到影响。未触及的结论可以复用，不机械重做全部动作；受影响的旧截图、旧日志或另一工作区结果不能继续充当当前结果。

并行分支各自成立，不推出合并后的契约成立。集成改变共享状态或接口时，针对改变了的组合重新取得相应依据，而不是把子任务报告相加。具体组织见[长任务](long-running.md)。

## EC-06 按任务需要取得依据

用户和项目已有检查要求照常执行。本 Skill 不额外规定 TDD、固定数量测试、全量基准或任务末尾审计；也不以“没有强制测试”为理由省略当前结论需要的事实。

已有记录能说明当前同一对象和条件，就可以复用。要求实际操作结果且环境允许时，通过既有入口观察；只需静态解释时，不擅自运行生产动作。需要新增费用、权限或敏感信息的取证不自动获得授权。

## EC-07 交付不夸大，也不人为拖延

完整完成所有可执行的授权工作。结论分为已修改、已在对应环境观察到、已外部生效，以及仍未知；仅保留会影响使用或判断的限制，不堆无关免责声明。

遇到真实外部障碍，准确说明已完成部分、未成立的具体结果和阻碍，不改写原目标宣称全部完成。没有障碍且结果已有相称依据，就结束，不为了“更放心”制造无限追加流程。文档核对、模拟推演和脚本语法检查各按实际性质表述，不能冒称真实宿主已生效或行为效果已验证。
