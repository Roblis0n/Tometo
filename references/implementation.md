# 实现：状态、错误、生命周期与功能接线

在本次修改涉及状态、异步处理、资源、应用权限、错误传播或端到端功能接线时读取。本页不是每个小改动必跑的清单。设计责任边界见[设计与变更](design-and-change.md)。

## IM-01 完成实际路径，而不只增加代码

把用户入口、处理逻辑、数据读取或写入、配置及必要资源连起来。新增函数但未注册到实际路由，创建设置项却未读取，添加界面却仍调用旧处理器，都不是对应功能已经实现。

按当前任务所承诺的完整行为实施。不得用固定成功返回、空方法、假数据、未接线分支或隐藏的功能删减冒充完成。明确属于展示样稿、模拟器或用户要求的 mock 时，可以使用模拟数据，但必须保持该任务的模拟边界；模拟产物不能被描述为真实外部能力。

## IM-02 状态先表达合法性

出现多个相关布尔值、可空字段或异步阶段时，先列当前业务实际允许的状态和转换。若可空字段组合会产生不可能状态，优先沿项目已有方式改为明确变体，如“空闲／处理中／成功带结果／失败带原因”，使每种状态携带它需要的数据。

不是所有对象都要变成状态机。只有非法组合已影响本次逻辑时才调整结构。保存成功、仅本地已更新和外部结果未知是不同事实，不能挤进一个 `success` 标记。需要保留历史或进行状态迁移时，连接到[兼容与交付](compatibility-and-delivery.md)。

## IM-03 错误必须保留语义和归属

分清缺字段、空值、未找到、权限拒绝、读取失败和写入结果未知。不要把读取失败改成空列表，或把未知远端状态改成成功。沿现有错误机制保留原因、必要上下文和可处理性；面向用户的错误由适合的边界翻译，内部细节不能泄漏凭据或敏感数据。

只有调用者能够正确恢复时才捕获并处理。无法处理就按契约传播，不用宽泛捕获加默认值掩盖损坏。错误提示应告诉下一步能采取什么动作；不为保留全部堆栈而把完整用户请求写入日志。

## IM-04 生命周期与资源所有权一致

对本次涉及的连接、文件、任务、订阅、定时器、锁或缓存，明确创建者、使用期、释放者及异常和取消路径。重复挂载或重试不应意外重复注册；结束一个窗口不应释放仍由应用级功能持有的资源；已取消任务不应继续回写过期状态。

修正实际存在的所有权问题，不机械为每个函数加包装层。已有项目资源管理机制能表达，就复用它。跨进程任务要区分真实处理进程和展示进程，不能因为两个模块可导入就把长工作放错执行边界。

## IM-05 异步结果和共享状态分别判断

涉及并发请求、重复提交或乱序回包时，判断哪一个结果仍对当前用户状态有效。依项目契约选择请求标识、版本条件、已有取消或互斥机制，不用随意睡眠假装完成同步。

如果多个请求会读写同一持久对象，再追“读取—检查条件—提交变化”的交错过程：两方同时读到旧值时，会不会重复分配、超额扣减、丢失更新或越过状态前提？单个窗口的禁用按钮、单进程锁或请求序号不自动保护其他实例。把约束放在实际共享状态的所有者处，沿项目已有条件更新、唯一约束、事务或等价原子操作表达；冲突后重新读取并判断业务意图，不能盲目覆盖，也不能在重试事务时重复已经发生的外部副作用。

状态切换与外部副作用须明确先后。外部操作超时可能未执行，也可能已执行而响应丢失；遵循[兼容与交付](compatibility-and-delivery.md)的状态查询和幂等边界。这里不指定所有项目使用某个隔离级别，不为没有共享并发语义的局部计算新增分布式锁、事务或协调平台。

## IM-06 边界转换不能靠猜

在本次修改涉及的输入、序列化、时间、数值范围或单位转换处，确认现行约定。缺失字段与显式空值、字符串标识与数值标识、秒与毫秒、绝对时刻与本地日期有不同含义。只处理实际可达输入和兼容承诺，不凭空支持所有可能格式。

避免在多个层重复隐式转换。转换应由约定的边界承担，并给直接消费者一致的值和失败语义。对超出表示范围的值，不静默截断或降精度；具体协议变化见[兼容与交付](compatibility-and-delivery.md)。

## IM-07 接线完成后说明真实状态

沿实际入口确认哪些代码路径已经接通，哪些结论来自静态读取、既有记录或本次运行观察。项目和用户原有的要求继续执行；不因本 Skill 不强制 TDD 就绕开原有义务，也不额外建设一套测试平台。

完成本次所有已授权且可执行的部分后交付；存在外部阻碍时，说明具体未成立的结果和已经完成的部分，不把“还有未知”当成停止所有工作的借口。对证据强度和范围的判断统一见[证据与完成](evidence-and-completion.md)。

## IM-08 应用权限落在可信执行边界

仅当本次改变身份、受保护对象、管理操作、共享数据或多租户路径时，明确“哪个主体，对哪个资源，以什么身份和归属，执行什么动作”。沿项目现有服务端、中间层或其他可信执行边界实施授权；前端隐藏按钮、已经登录、知道对象 ID 和 Agent 有权改代码，都不等于应用用户有权执行该操作。

复用项目已有权限机制，覆盖本次新增或改变的实际入口，不只保护一个页面。公开资源按既定公开契约处理；受保护操作的身份、归属或授权结果不明时，不把它变成允许。异步任务必须保留正确的权限与资源范围，实际生效时按项目契约判断权限是否仍适用。

说明权限行为已成立时，依据须能区分合法访问与本次相关的拒绝情形；模拟环境若不执行该权限语义，成功结果不能证明拒绝边界有效，见[证据与完成](evidence-and-completion.md)。不因此对无关文案任务启动安全审计，也不新建身份系统、不用真实他人数据做探测、不扩大生产访问。
